Guide CsAgent

CsAgent

Guide de l'utilisateur · version 0.9.4

Sommaire

    Démarrer

    CsAgent est un agent de codage autonome. Tu lui décris une tâche en langage naturel ; il lit et écrit des fichiers, lance des commandes et te rend compte, étape par étape. Il fonctionne sous Windows, Linux et macOS avec n'importe quel serveur de modèles compatible OpenAI, par exemple l'API Albert.

    Première session

    1. Définis ta clé d'API. Sous Windows (cmd) : set ALBERT_API_KEY=ta-clé. Sous Linux et macOS : export ALBERT_API_KEY=ta-clé. Elle est inutile avec un serveur local comme Ollama.
    2. Place-toi dans le dossier de ton projet. L'agent ne peut lire et écrire que dans ce dossier et ses sous-dossiers.
    3. Lance CsAgent. csagent --leanui ouvre l'interface web légère sur http://localhost:5050. Sans option, tu travailles dans la console.
    4. Décris la tâche. Par exemple : Crée un projet console C# qui affiche Hello, World! L'agent réfléchit, exécute des outils, puis rend compte.
    5. Réponds aux demandes de confirmation. Avant de modifier un fichier, l'agent demande ton accord. Dans la console, tape exit pour quitter.
    Une seule demande. csagent --prompt "liste les fichiers ici" exécute la demande, affiche la réponse et quitte. C'est la forme à utiliser dans un script.
    Attention. csagent "du texte" ne lance pas de demande : un argument seul, sans tiret, est le nom du dossier de mémoire. Utilise toujours --prompt.

    Les modes de fonctionnement

    Le travail de l'agent est le même partout. Seule change la façon dont tu le suis.

    ModeLancementPour quoi faire
    ConsolecsagentSession interactive en texte ; exit pour quitter
    Web UIcsagent --uiInterface sombre avec le flux des réflexions, des appels d'outils et des résultats en temps réel, et la coloration du code
    Lean UIcsagent --leanuiVariante légère, dans le style d'un terminal, avec les commandes /help et /skills
    APIcsagent --api --yesServeur sans interface, piloté par un autre programme (orchestrateur)
    Une demandecsagent --prompt "…"Une requête, une réponse, puis fin

    Les interfaces web écoutent sur le port 5050. Change-le avec --port (ou -p).

    Joindre une image

    Dans les interfaces web, le bouton 📎 joint une image à ta demande (PNG, JPEG, GIF ou WebP, 10 Mo au maximum). CsAgent envoie alors la demande à un modèle capable de vision (gemma-4-31b-it par défaut).

    Une question de suivi sur une image demande l'image. Seule l'image envoyée avec le message courant fait choisir le modèle de vision. Au tour suivant, le modèle ne voit plus que la description donnée avant : colle de nouveau l'image pour qu'il la revoie.

    Dicter une demande

    Le bouton 🎙 enregistre depuis le navigateur. L'audio est transcrit par le serveur (Whisper), puis tu choisis :

    • Use as instruction : le texte est placé dans la zone de saisie ;
    • Keep as text : la transcription est gardée dans transcripts/ et jointe à ta prochaine demande.

    À côté du bouton, FR / EN / Auto indique la langue que tu parles. Au-delà de quelques minutes d'enregistrement, ffmpeg doit être installé (ou indiqué par CSAGENT_FFMPEG). Pour supprimer les anciens enregistrements, définis CSAGENT_AUDIO_KEEP_DAYS ; les transcriptions ne sont jamais supprimées.

    Mode API pour orchestrateurs

    --api démarre le serveur SSE sans aucune interface. Une adresse non locale (--host 0.0.0.0) exige une clé : --api-key, ou mieux la variable CSAGENT_API_KEY, car un argument est visible dans la liste des processus. Les clients envoient Authorization: Bearer <clé> ou X-API-Key: <clé>.

    csagent --api --yes --host 0.0.0.0 --port 8080 --api-key s3cret
curl -N -H "Authorization: Bearer s3cret" "http://localhost:8080/api/chat?prompt=create+hello.txt+containing+hi"

    Le serveur parle en HTTP simple : au-delà de ta machine, place-le derrière un proxy TLS. Il garde une conversation : envoie une requête à la fois, ou lance une instance par tâche avec son propre --mem et son propre --port.

    Les commandes de la Lean UI

    Tape / dans la zone de saisie : un menu propose les commandes, filtrées au fur et à mesure.

    CommandeEffet
    /new [nom]Crée un nouvel onglet de session, avec un nom si tu en donnes un
    /clearEfface la sortie du terminal
    /skills [filtre]Liste les skills de skills/INDEX.md ; /skills fail filtre sur le nom ou la description
    /helpOuvre le menu des commandes

    Dans le menu : ↑ et ↓ déplacent la sélection, Entrée ou Tab choisissent, Échap ferme, et la souris fonctionne (survol, clic). Une commande tapée en entier est envoyée telle quelle ; un début de commande (/ne) est complété par le menu.

    Choisir un skill n'envoie rien. Le champ de saisie reçoit une instruction, par exemple Use the skill "Failure Recovery" (skills/failure-recovery.md): . Complète-la avec ta demande, puis Entrée. L'agent lit alors le fichier du skill. Pour ajouter un skill, mets un fichier dans skills/ et une ligne dans skills/INDEX.md ; il apparaît au prochain /skills.

    Les modèles

    CsAgent choisit le modèle pour chaque message, sans appel supplémentaire ni délai. Trois profils existent, identiques dans tous les modes.

    ProfilPar défautUtilisé quand
    Codedeepseek-v4-flashCode, fichiers, shell, e-mails, audio, liens, et tout ce qui n'est pas clairement une question générale. C'est lui qui exécute les outils
    Chatopenweight-largeRecherches (web, actualités, météo, un lien à lire) et conversation générale : explication, culture, rédaction, conseil
    Visiongemma-4-31b-itLe message courant contient une image

    Comment le choix est fait

    1. --model <nom> l'emporte toujours.
    2. Une image dans ton message choisit le modèle de vision.
    3. Tes propres règles de LLMRoutingRules/rules.json, testées dans l'ordre.
    4. Une réponse courte qui poursuit le tour précédent (8 mots ou moins, comme « ok » ou « merci ») garde le modèle de ce tour.
    5. Un nom de fichier, un chemin, du code ou une action sur ton ordinateur choisit le modèle de code.
    6. Une recherche explicite choisit le modèle de chat.
    7. Un message qui parle de code, de commande, d'e-mail, d'audio, de git ou de tests choisit le modèle de code.
    8. Sinon, c'est une conversation générale : le modèle de chat répond.

    Le modèle utilisé est indiqué sous chaque réponse ([model: …]). Pour comprendre un choix sans appeler de modèle :

    csagent --explain-routing "ouvre Chrome"

    Régler le choix

    RéglageEffet
    --code-model, --chat-model, --vision-modelChange le modèle d'un profil (variables CSAGENT_MODEL_CODE, CSAGENT_MODEL_CHAT, CSAGENT_VISION_MODEL)
    --no-routeToujours le modèle de code (ou CSAGENT_ROUTING=off)
    --modelUn seul modèle pour tout
    --init-routingCrée le dossier LLMRoutingRules/ avec models.json, keywords.json et rules.json ; les modifications s'appliquent au message suivant
    --rules <dossier>Utilise un autre dossier de règles

    Une erreur dans un de ces fichiers n'arrête jamais l'agent : un avertissement s'affiche une fois et les valeurs intégrées sont conservées.

    Utiliser un modèle local avec Ollama

    ollama pull qwen2.5-coder:14b
csagent --endpoint http://localhost:11434/v1 --model qwen2.5-coder:14b
    • Aucune clé n'est nécessaire pour un serveur local (localhost, 127.x, ::1).
    • Choisis un modèle qui gère l'appel d'outils : l'agent en dépend (par exemple qwen2.5-coder, qwen3, llama3.1).
    • Pour les images, ajoute --vision-model llava.
    • Sur un serveur personnalisé, il n'y a pas de modèle de chat tant que tu n'en définis pas un : tous les messages utilisent le modèle de code.
    • Définis CSAGENT_ENDPOINT pour ne pas retaper l'URL.

    Travailler en sécurité

    Quatre garde-fous limitent les dégâts possibles d'une erreur de l'agent.

    • Confirmation des actions destructrices. Ces outils demandent ton accord : write_file, edit_file, move_file, delete_file, unzip, git_commit, write_clipboard, send_email et save_attachment. Chaque appel à un outil d'un serveur MCP en demande un aussi.
    • Périmètre. Les opérations sur les fichiers sont limitées au dossier courant et à ses sous-dossiers.
    • Filtre des commandes shell. Les motifs dangereux sont refusés : sudo, chmod, shutdown, mkfs, /etc/ sous Linux et macOS ; format, del /f, reg delete, diskpart, shutdown, \windows\system32\ sous Windows.
    • Limites. Une commande est arrêtée après 60 secondes. La lecture d'un fichier de plus de 500 Ko est refusée ; l'agent utilise alors grep ou head.
    Sans surveillance. --yes (ou -y) approuve tous les appels d'outils sans demander. Il ne supprime que les questions : le périmètre et le filtre shell restent actifs. Pour essayer sans rien modifier, lance --dry-run : les outils sont simulés.

    Avec --quiet (-q), la sortie se réduit aux messages de l'assistant, aux avertissements et aux erreurs ; une action qui demande ta confirmation reste visible.

    Ce que l'agent sait faire

    Tu n'appelles pas les outils toi-même : l'agent choisit ceux dont il a besoin pour ta demande.

    DomaineOutils
    Fichiersread_file, read_json, write_file, edit_file, list_dir, tree, search_files, copy_file, move_file, delete_file, zip, unzip
    Commandessh, run_terminal, close_terminal, parse_output
    Gitgit_status, git_diff, git_log, git_branch, git_commit
    Webweb_search, fetch_url, http_request
    Courrierread_msg (fichiers Outlook .msg), save_attachment, send_email
    Audiotranscribe_audio (Whisper ; ffmpeg pour les longs fichiers, 100 Mo au maximum)
    Bureauread_clipboard, write_clipboard, excel_command, close_excel
    Modèleslist_models, switch_model

    Connecter un serveur MCP

    --mcp <url> (ou CSAGENT_MCP_URL) connecte un serveur MCP en HTTP, par exemple csagent --mcp http://localhost:8000/mcp. Ses outils sont proposés au modèle sous le nom mcp_<nom>, ce qui empêche un serveur de remplacer un outil intégré.

    • Chaque appel MCP demande confirmation, sauf avec --yes.
    • Ce qu'envoie le serveur est traité comme une donnée, jamais comme une instruction. Ne connecte que des serveurs de confiance.
    • Limites : un seul serveur, HTTP seulement, pas d'en-tête d'authentification, outils uniquement.

    La mémoire

    CsAgent garde le contexte d'une session à l'autre dans un dossier de mémoire, agent_memory/ par défaut.

    agent_memory/
├── conversation.json   historique complet, envoyé au modèle
├── exact.json          les 50 dernières étapes, mot pour mot
├── semantic.json       schémas erreur / solution déjà rencontrés
└── summary.json        résumé de session : décisions, contraintes, en attente, approches échouées
    • Une tâche, un dossier. Pour continuer une tâche, garde le même nom. Pour en commencer une sans rapport, utilise un autre nom avec --mem <nom> (ou en argument seul), ou supprime le dossier.
    • Contexte borné. Les plus anciens messages sont élagués au-delà d'environ 96 000 caractères. La mémoire hybride rappelle à l'agent ce qu'il a déjà essayé, pour qu'il ne répète pas ses erreurs.
    • Résumé de session. À la fin d'une exécution, un dernier appel au modèle condense la conversation en quatre listes, relues au démarrage suivant. --no-distill évite cet appel : un résumé existant est toujours lu, mais il n'est ni créé ni modifié. Supprime summary.json pour l'oublier.
    • Fichiers sûrs. Ils sont écrits de façon atomique. Un fichier illisible est renommé en .bad et l'agent repart avec une mémoire vide, sans s'arrêter.

    Limites de débit et quota du jour

    Quand le serveur répond par une erreur 429, CsAgent lit le message pour savoir de quelle limite il s'agit.

    LimiteCe que fait CsAgent
    Par minuteRéessaie avec un délai croissant et l'en-tête Retry-After : 6 essais par défaut
    Par jourNe réessaie pas : essayer ne servirait à rien avant la remise à zéro. Il bascule sur un autre modèle s'il y en a un, sinon il s'arrête avec une explication

    La bascule automatique

    Quand le quota du jour d'un modèle est épuisé, CsAgent renvoie la même requête au modèle de code (deepseek-v4-flash) sur le serveur Albert par défaut, affiche un avertissement et poursuit. Le modèle épuisé est écarté pendant 1 heure. Il n'y a pas de bascule pour une limite par minute, ni quand la conversation contient une image, et au plus 2 fois par exécution.

    • CSAGENT_FALLBACK_MODEL=<modèle> choisit le modèle de remplacement, sur n'importe quel serveur.
    • CSAGENT_FALLBACK_MODEL=off désactive la bascule : l'agent s'arrête au premier 429 du jour.
    • Sur un autre --endpoint sans cette variable, il n'y a pas de bascule.

    En fin de tour, la console affiche les jetons consommés : [tokens: this turn in 23,412 / out 310 · session in … / out …]. Les jetons d'entrée sont ceux qui comptent pour le quota, car chaque étape renvoie tout l'historique.

    Réglages : --max-retries <n> (6 par défaut) et --retry-delay <ms> (1000 par défaut).

    Scénarios courants

    Travailler sans confirmations ni bruit

    csagent --leanui --yes --quiet

    Lancer une tâche dans un script

    csagent mon_projet --prompt "liste les fichiers ici et résume le README" --yes

    Essayer sans rien modifier

    csagent --dry-run

    Suivre une tâche dans un dossier dédié

    csagent --task migration-db

    L'hôte crée .csagent/tasks/migration-db-<date>/ avec un plan et un suivi d'avancement. Ces fichiers sont créés par CsAgent, jamais par le modèle.

    Utiliser un autre serveur de modèles

    csagent --endpoint http://localhost:11434/v1 --model qwen2.5-coder:14b

    Comprendre pourquoi un modèle a été choisi

    csagent --explain-routing "résume https://exemple.fr"

    Séparer deux projets

    csagent --mem projet_a
csagent --mem projet_b

    Dépannage

    Message ou symptômeCause et solution
    « API Key not set »Définis ALBERT_API_KEY avant de lancer l'agent.
    « API 401 »La clé est invalide ou a expiré.
    « API 429 »Limite de débit : voir la section sur les limites. Un quota du jour épuisé bascule sur un autre modèle ou s'arrête.
    « command timed out (60s) »La commande a duré plus de 60 secondes. Découpe la tâche en étapes plus petites.
    « file too large »Le fichier dépasse 500 Ko. L'agent doit utiliser grep, head ou find.
    « Path is not allowed »Le chemin est hors du dossier courant. Lance l'agent depuis le bon dossier.
    Le navigateur ne s'ouvre pasVa à http://localhost:5050 (ou le port de --port).
    L'image ne se joint pasFormats acceptés : PNG, JPEG, GIF, WebP, 10 Mo au maximum.
    Mauvais modèle choisiLance csagent --explain-routing "ton message". Tes règles passent avant la logique intégrée ; --model ou une image les devancent.
    « LLMRoutingRules : … »Un fichier du dossier contient une erreur. Les valeurs intégrées sont gardées ; corrige le fichier, il est relu dès qu'il change.
    csagent "texte" ne fait rienUn argument seul est un nom de mémoire. Utilise --prompt.
    « Session summary not updated »Le modèle n'a pas répondu en 60 secondes ou a répondu autre chose que le JSON attendu. Ta tâche n'est pas touchée et le résumé précédent est conservé.
    Fichier .bad dans la mémoireLe fichier n'était pas du JSON valide. Corrige-le ou supprime-le.
    « Expected multipart/form-data »Un POST /api/chat doit être en multipart/form-data. Les interfaces web le font seules.
